# 資料採集與可行性驗證（Phase 2 技術驗證）

本資料夾包含兩支採集腳本，目的是**先驗證資料拿不拿得到**，再進入模型開發。
這對應你們規劃表的 Phase 2「技術驗證」，也是整個專題風險最高的關卡。

## 為什麼要在你自己的電腦上跑

這些腳本需要連到 Yahoo Finance 與 PTT。開發沙箱的網路被限制在白名單內，
連不出去（測試時會看到 `Host not in allowlist`）——這是環境限制，**不是程式錯誤**。
程式的計算邏輯已用離線假資料測試通過（指標計算、推噓解析、關鍵字過濾皆正確）。

## 安裝

```bash
pip install yfinance pandas requests beautifulsoup4
```

建議用 Python 3.10 以上。若硬體資源有限，模型訓練階段可改用 Google Colab（免費 GPU）。

## 執行步驟

### 1. 抓股價（先跑這個，最穩）

```bash
python fetch_stock.py
```

成功會輸出 `stock_0050_TW.csv`、`stock_2330_TW.csv`、`stock_TSM.csv`，
每檔含收盤價、5/20 日均線、RSI14、日報酬率，以及 `Target_Up`（隔日漲跌標籤，
這就是模型要預測的 y）。終端機會印出「成功 N/3 檔」的可行性結論。

### 2. 抓 PTT 輿情

```bash
python fetch_ptt.py
```

預設只抓最新 3 頁來驗證可行性（正式採集時把 `PAGES_TO_CRAWL` 調大）。
程式會用關鍵字（0050、台積、2330、TSMC…）過濾出與標的相關的文章，
輸出 `ptt_stock.csv`，含標題、日期、推噓數、內文摘要。

> 注意：腳本已內建請求延遲與 User-Agent，請勿把延遲改太短。
> 這呼應你們 SWOT 的「反爬機制」威脅——禮貌爬蟲才能長期穩定取得資料。
> 若 PTT 改版導致解析失敗，需更新 `fetch_ptt.py` 裡的 CSS selector。

## 驗證通過後的下一步

1. **情緒分析**：把 `ptt_stock.csv` 的 `body` 餵入中文情緒模型
   （建議先用預訓練的 `bert-base-chinese` 微調，或先用 LLM API 標記，
   解決你們劣勢分析點出的「標記數據不足」問題），產生每篇情緒分數。
2. **彙總成每日情緒**：把同一天的文章情緒加權平均（可用推噓數當權重），
   得到「每日輿情情緒分數」。
3. **特徵合併**：依日期把「每日情緒分數」併到 `stock_*.csv`，
   形成 `技術指標 + 情緒` 的訓練特徵表。
4. **訓練模型**：先用 LightGBM / RandomForest 拿基線，再上 LSTM；
   記得加 SHAP 做可解釋性（對應你們的「黑盒子」改善計劃）。
5. **做成應用**：用 Streamlit 把股價、情緒疊圖與預測結果做成可互動 web app。
